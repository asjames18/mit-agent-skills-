# Security Policy

## Public repository boundary

Do not submit secrets, credentials, session data, private account identifiers, confidential organizational information, non-public personal data, internal endpoints, or real security incidents.

Examples and fixtures must be synthetic. If a contribution depends on private context, keep that context in its private project and expose only the reusable, sanitized workflow here.

## Reporting a vulnerability

Do not open a public issue containing exploit details or sensitive data. Use GitHub's private vulnerability reporting or security-advisory feature for this repository. If neither is available, contact the repository owner through a private channel listed on their GitHub profile.

## External actions

Skills in this repository may describe guarded workflows, but they never grant permission to publish, message, purchase, deploy, delete, change an account, or perform another external mutation. Authorization must come from the user at the appropriate action boundary.
